These notes study human-agent coordination and resource allocation through
digital tokenomics as part of a verified decentralized superintelligence
(DSI) system. We develop its models, specifications, executable operations, and
proofs natively in [Lean 4](https://lean-lang.org/).

## Participant registries

The executable prototype runs independent node processes on one machine. Each
node registers and looks up participant IDs, exchanges registry snapshots with
configured peers, and saves and restores its state locally. For example, if one
node registers ID 1 and another registers ID 2, a successful exchange gives both
nodes the two IDs. Repeating an ID adds no duplicate entry.

The library proves that registration and snapshot merging preserve registry
uniqueness. From a consistent state in the system execution model, saved
registrations survive every finite continuation and remain queryable whenever
their node is online. A
successfully delivered and saved snapshot gives its recipient the same guarantee
for every incoming ID. These proofs assume intact storage, one writer per node,
and atomic save-and-publish operations. The TCP and filesystem implementation is tested;
its correspondence to the model is not formally proved, and eventual delivery
remains unproved.

## Identifier collision probability

[Identifier collision probability](../VDSI/IdGeneration/Note.mdx) defines a
finite model of independent uniform samples and proves the birthday bound. For
at most one billion 256-bit draws across the whole system, the probability of
any collision is below $2^{-128}$. Conversion to a participant ID preserves the
sampled value. This is a probability-model result: the running prototype accepts
manually supplied IDs and has no random ID generator.

## Implementation scope

The current system has no blockchain, consensus, wallet authority, ledger,
payments, or token issuance and redemption. Participant registration and its
safety properties provide basic identity records for the coordination system;
they do not yet establish account ownership or monetary rules. The separate
proof-task experiment checks prewritten Lean submissions with the kernel and
does not call an AI prover.
